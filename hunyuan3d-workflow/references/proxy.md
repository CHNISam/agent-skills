# 代理 MCP：能力与边界

上游：https://github.com/montezl/hunyuan3d-proxy

研究加固分支：https://github.com/CHNISam/hunyuan3d-proxy/tree/change/task-206

2026-10-17，基于上游 `9a054e0` 的有限实测：

| 能力 | 证据结论 |
|---|---|
| MCP 连接 | SDK 握手、健康检查、8 工具目录通过 |
| 国内真实账号 | 本人微信扫码登录成功；内存会话读取主站/Studio 额度及 MCP 任务列表 |
| 额度辅助请求 | 一条接口 HTTP 500；不得把整体记为全通过 |
| 代理生成、纹理提交、下载 | 未完整验收；这些操作当时通过官方网页完成 |
| 国际版代理 | 未验证；不要只替换域名就宣称支持 |

按当前所需能力选择入口；只读成功不能证明消费闭环成功。重新部署时先核对固定版本、变更与实际工具目录；研究测试不代表已有持续运行的账号服务。

研究分支启动须绑定 `127.0.0.1`，HTTP/MCP 全路由 Bearer、精确 Host/Origin 校验、禁用面板/静态文件及裸透传。默认 `RESEARCH_ALLOW_SPEND=0`、`RESEARCH_ALLOW_SESSION_IMPORT=0`，会话仅内存；这些环境变量属于研究分支，不能假定原版具备相同保护。

`research/README.md` 说明显式启用的微信扫码只读探针。它不提交生成/纹理/云请求，结束即退出并清除会话。让用户通过可见官方扫码页面/二维码完成；浏览器安全阻止时交给用户正常操作，不绕过限制。QQ 网页登录成功不代表代理支持 QQ 登录，也不能由额度相同判断账号相同。

调用额度/任务查询时区分：本地 HTTP 状态、上游 HTTP 状态、业务状态。业务 `status=2` 不等于 HTTP 2；空列表也可能掩盖上游错误。原始失败证据保留，修复后未重跑的检查仍标待测。

以后若要验证消费能力，先确认预算及接口保护，仅开放所需操作，以单任务验证提交→查询→下载→文件验收，再更新能力表。不要把会话、Bearer、签名下载链接或二维码写入 Git/长期报告。云 API 的免费包与后付费开关须另核实。
