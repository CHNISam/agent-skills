# 16 维产品评审（product-review-16d）

## 这个 skill 是什么

一套**固定的 16 维评审 schema**。每一维都有：
- **核心问题**：本维要回答的那一句话
- **可检测信号**：在视觉、DOM、原型、埋点里能看到的客观证据
- **严重度规则**：什么情况记什么级别（阻断 / 高 / 中高 / 中）

**用户已经反复强调：每一行都是千锤百炼，不得遗漏、不得改写**。如果你觉得某项不适用，标注"N/A + 原因"，不要删表格行；如果你觉得有新维度，单独追加在"补充观察"里，不要塞进 16 维。

## 16 维评审表（权威定义，逐字保留）

| ID | 维度 | 核心问题 | 可检测信号 | 严重度规则 |
|----|------|----------|------------|------------|
| UG-01 | 用户目标 | 用户能在 5 秒内说出"这页帮我做什么"吗 | 视觉：h1/hero 区域、主按钮文字；DOM：`<title>`, `<h1>`, 面包屑 | **高**：入口页/落地页失败；**中**：次级功能页失败 |
| PA-01 | 主任务路径 | 主任务是否以最短且确定的路径完成 | 原型点击深度、固定底部的 CTA、模态弹窗数量、滚动深度 | **阻断**：任务逻辑不通；**高**：强制性多路径分叉 |
| IA-01 | 信息层级 | 用户能快速定位标题、分组和主要动作吗 | 层级字号/间距、h1-h3 顺序、标签文本、链接的上下文 | **高**：找不到关键操作；**中**：扫读体验极差 |
| FB-01 | 交互反馈 | 操作后系统反馈是否及时且可信 | 按压态/悬浮态、Loading 骨架屏、Toast、进度条、按钮禁用态 | **高**：导致用户重复点击或误以为系统死机 |
| ST-01 | 状态完整性 | 是否覆盖了 8 类关键状态（如空态、错误、加载） | 骨架屏、空态插画+CTA、离线提示、局部报错按钮 | **阻断**：缺关键状态导致用户掉进死路 (Dead End) |
| ER-01 | 错误恢复 | 错误是否能定位、解释、建议并保留已填数据 | Inline Error、错误摘要 (Summary)、保留输入值、撤销/重试按钮 | **高**：支付/表单发布失败且不可恢复或数据丢失 |
| AX-01 | 颜色独立性 | 关键信息是否不依赖颜色单独成立 | 灰度模拟检测、红绿状态是否伴随图标/文本、图表图例 | **高**：严重影响色弱/色障用户完成核心任务 |
| AX-02 | 对比度/焦点 | 文本对比度与键盘焦点框是否过线 | 对比度数值 (≥4.5:1)、焦点环 (Focus Ring) 可见性、2px 轮廓 | **高**：主按钮或主要文本对比度不合格 |
| AX-03 | 读屏与语义 | 语义标签是否支持读屏完成常见任务 | `aria-label`, `alt` 属性, 可访问树 (Accessibility Tree) | **阻断**：核心任务无法通过读屏软件完成 |
| AX-04 | 目标尺寸 | 触控目标大小与键盘路径是否可用 | bbox (包围盒) 尺寸 (Web≥24px/iOS≥44pt)、Tab 键顺序 | **高**：误触严重或键盘导航陷入陷阱 (Trap) |
| VD-01 | 视觉专业度 | 页面看起来是否一致、克制、可托付 | 间距方差 (Spacing Variance)、像素对齐、组件样式统一性 | **中**：影响品牌信任感和决策速度 |
| CP-01 | 文案清晰度 | 文案是否使用用户语言并能指导动作 | CTA 动词、术语一致性、错误提示的可执行性 (Actionable) | **中高**：导致用户产生歧义或误操作 |
| PF-01 | 性能与响应 | 页面是否足够快，慢的时候是否可理解 | LCP ≤2.5s、INP ≤200ms、埋点时延、骨架屏出现时机 | **高**：性能低下导致转化率或完成率显著下降 |
| I18N-01 | 国际化 | **语言方向、日期格式和文案扩充是否适配** | `lang` 属性、RTL 镜像、溢出检测、本地化货币/日期格式 | **中高**：目标地区用户无法正常使用或排版崩溃 |
| PS-01 | 隐私与安全 | 权限采集和敏感动作是否值得信任 | 权限请求时机 (JIT)、用途说明字符串、敏感操作二次确认 | **阻断**：涉及合规风险或关键隐私泄露 |
| MT-01 | 可测量性 | 设计是否可验证、可回归、可优化 | 埋点 Schema：必须包含曝光、开始、提交、成功、失败、放弃 | **中**：无法通过数据验证改版成效 |

## 关键注意事项（容易被忽略的"魂"）

### 1. I18N-01 不是只看语言
新人最容易把 I18N-01 简化成"有没有英文翻译"。**错**。这一维至少 4 个子项必须全检：
- **`lang` 属性**：DOM 上声明了正确的语言代码（影响读屏发音、字体回退、断词）
- **语言方向 / RTL 镜像**：阿拉伯语/希伯来语场景下，整套布局（图标方向、进度条、返回箭头、Tab 键序）是否做了镜像
- **文案扩充溢出**：同一句话从中文翻成德语/俄语字数可能 +60%，按钮、卡片、表头是否会撑破或截断
- **本地化货币/日期格式**：`¥1,234.56` vs `1.234,56 €`、`2026-05-13` vs `13/05/2026` vs `13.05.2026`、星期起始日

这四项任意一项缺失就判 **中高**。如果产品当前只做单语言、且明确不会出海，可以记 N/A 但**必须写明"明确不出海"的依据**，不要默认跳过。

### 2. ST-01 的"8 类关键状态"
评审时要逐条点名（不全列就容易漏）：**加载中 / 空态 / 部分加载 / 错误 / 离线 / 无权限 / 超长内容 / 极端数值**。任何一类在该页面上"理论上会发生但没有设计"，都按规则记 **阻断**。

### 3. PA-01 / FB-01 的常见坑
- "强制性多路径分叉"指**完成同一个主任务必须做选择**（比如非要先选身份再下单），不是"页面上有多个入口"
- "导致用户重复点击或误以为系统死机"指**完全没有反馈**或**反馈晚于 1s 且无 loading**，不是"反馈不够好看"

### 4. 文案禁用词（项目级硬约束）
评审输出里**永远不要用"点位"和"实际可达性"**这两个词——这是项目 CLAUDE.md 的硬约束，违反等于评审作废。

## 标准评审流程

1. **明确评审对象**：截图 / wxml 路径 / 原型 URL / 已上线功能名 + 用户角色 + 主任务。如果用户没给清，先问一句再开工。
2. **逐维过 16 行**：每一维按下面"单维输出模板"产出，不要把多维合并成一段话。
3. **汇总严重度**：把所有"阻断 / 高"项摞到最前面，按"修复 ROI"排序，给出建议的修复批次。
4. **补充观察**（可选）：不属于 16 维但确实是问题的，放在末尾"补充观察"小节，**不要硬塞进 16 维**。

## 单维输出模板

每一维都按这个结构输出，缺哪一块用"—"占位：

```
### [ID] [维度名]
- 判定：✅ 通过 / ⚠️ 有问题 / 🚫 阻断 / N/A（说明原因）
- 证据：在哪看到了什么（截图坐标 / DOM 节点 / 文件:行号 / 埋点字段）
- 严重度：阻断 / 高 / 中高 / 中（必须引用上表的"严重度规则"原文判定，不要自创等级）
- 建议：可执行的修复动作（一句话，动词开头）
```

## 最终报告结构

```
# [对象名] 16 维评审报告

## 摘要
- 阻断项：N 个
- 高：N 个 / 中高：N 个 / 中：N 个
- 一句话结论

## 优先修复清单（按严重度 + ROI 排序）
1. [ID] [维度] — [一句话问题] — [一句话修复]
2. ...

## 逐维详情
（按 UG-01 → MT-01 顺序，使用上面的"单维输出模板"）

## 补充观察（可选）
不属于 16 维但值得记录的发现。
```

## 反模式（看到这些立刻改）

- ❌ 只输出"我觉得这里不太好" → ✅ 必须落到具体 ID 的"可检测信号"上
- ❌ 自创严重度（"轻微"、"建议改"） → ✅ 只能用 阻断/高/中高/中
- ❌ 16 维合并成 5 段散文 → ✅ 16 个独立小节，缺项写 N/A
- ❌ 把 I18N-01 简化为"语言翻译" → ✅ 四子项（lang/RTL/溢出/格式）逐项过
- ❌ 用"点位"、"实际可达性" → ✅ 项目硬禁
- ❌ 跳过 MT-01 不提埋点 → ✅ 没埋点本身就是问题，要按规则记中
