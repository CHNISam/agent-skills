# Product Craft Polish

把"能用但差点意思"变成"像成熟团队做的产品"。核心信念：专业感不是一次大改版，而是
**几十个指向同一方向的小决定**——低无谓视觉复杂度 + 平台/品类原型熟悉度 + 内部一致性 +
可信的内容呈现 + 克制而有意的交互反馈。

完整理论与全部文献见 `references/full-essay.md`（原文逐字保留，深挖时读它）。本文件是操作流程。

## 铁律：受约束的精修，不是重设计

开工前先冻结非目标。**不得改动**：信息架构、任务流程、字段列表、导航模型、权限、
业务规则、埋点、API 行为、核心文案语义、功能增减。只允许动这些杠杆：间距、对齐、
排版、色彩角色、图标族、圆角、描边、层级/海拔、内容分块、状态样式、加载占位、克制动效。

若发现真正的功能/可用性硬缺陷，单独指出并交还用户决定，**不要顺手在打磨里改逻辑**。

## 七类 gap 诊断框架（先归因再修）

每条问题必须先归到下面某一类——不同的"感觉不对"对应不同的修法：

| Gap | 症状 | 修法方向 |
|-----|------|----------|
| Perception 感知 | 检视后能懂，但一眼看不懂这是什么页、主操作是谁 | 提一个主导区，压次要块；贴近品类原型 |
| Rhythm 节奏 | 间距技术上没错但随意，每个 gap 都不一样 | 间距重映射到 4/8px token 阶梯，定一个密度模式 |
| Hierarchy 层级 | 所有元素同一音量，没有阅读顺序 | 用尺寸/对比/间距/位置建层级，别加框加色 |
| Surface 表面 | 卡片/阴影/圆角是装饰不是语义，显得廉价模板 | 小而固定的表面集（平铺/描边/抬升各司其职） |
| Language 语言 | 字体/图标/文案不是一个嗓子，不高级 | 一套编辑化排版 + 一个图标族 + 统一微文案语气 |
| Behavior 行为 | 能用但反应不精确，态突兀或缺失 | 补全 hover/focus/pressed/selected/loading/态，态与静止同语言 |
| System 系统 | 单页都还行，但全局不统一（这页这阴影那页那圆角） | 收敛到 token/组件变体，把"品味"变可复用标准 |

## UI Craft 检查清单（逐项扫，给可执行结论）

假设页面已能用。逐项问"是否刻意、连贯、有商业打磨感"，每项给：典型失败 → 改法 →
验收点。完整每项判据见 full-essay「UI Craft and visual polish checklist」。快扫顺序：

1. 第一印象与焦点（5 秒能说出页面用途+主操作？）
2. 构图与平衡（眯眼/模糊后仍有清晰阅读路径与大中小块平衡？）
3. 空间节奏与密度（间距能用 token 命名？密度是选定的不是混搭？）
4. 留白与分组（相关靠近、无关分开，不靠多余卡片/分隔线撑结构？）
5. 排版层级（角色化、可视样式数收敛，靠字号字重不靠颜色补救？）
6. 竖向节奏与行宽（正文 ~60–80 字符，行高随字阶校准？）
7. 内容封装（信息是有意义的 chunk，不是裸字段堆叠？）
8. 色彩角色纪律（颜色按 primary/secondary/surface/success/warning/danger/info 角色，不按局部喜好？）
9. 表面深度与卡片（同屏表面种类少且各有理由，卡片只裹单一主题？）
10. 形状语言（圆角/描边一套逻辑，遮掉文字仍认得出是一个产品？）
11. 图标（同一族、同权重、与字号对齐，不混线性/实心/emoji？）
12. 组件一致性（重复模式保持重复，padding/圆角/按钮变体不漂移？）
13. 状态打磨（全套交互态都设计过，且与静止同视觉语言？）
14. 动效与等待（动效强化因果非炫技，~0.1s 内起效，等待态保上下文？）
15. 品牌嗓音与信任信号（文案/状态/语气传达目标形容词，时间戳/披露不寒酸？）
16. 像素收尾与实现 QA（对齐/基线/截断/响应/主题在多断点多态都过？）

## 工作流：把品味转成任务

按此顺序执行，每步留证据，不要跳到"直接改好看点"：

1. **冻结范围** — 明写非目标清单（见铁律）。先声明不改什么。
2. **取证诊断** — 在相关断点/状态截真实页面，跑三诊断：5 秒印象测试、模糊/眯眼层级测试、
   组件-token 盘点。产出必须具体："5 秒内认不出主操作"/"模糊后分组塌掉"/"全页 7 种竖向 gap"，
   不是"看着乱"。
3. **按 gap 归类** — 每个问题打上七类标签。同一抱怨归错类就会修错方向。
4. **选对标杆** — 对标同 job-to-be-done、同信息密度、同平台规范的产品 + 一套 house system；
   B2B 后台别对标营销落地页。
5. **写视觉方向句** — 把主观感觉压成一句目标："通过降噪+强化排版层级+统一表面系统，让此页
   更沉静、更可信、更企业级。"用明确形容词，不用模糊品味词。
6. **方向落成 delta 编辑** — 每个改动写成 before → after，绑定具体组件/token/数值。例：
   "段标题 20/28 semibold → 16/24 semibold；区块 gap 20 → space.300；次要卡片描边 →
   平铺仅留一张抬升汇总卡；混合图标 → 单一描边族"。禁止笼统"优化一下"。
7. **快验证** — 改后重跑 5 秒测试、轻量满意度（形容词词表往 trustworthy/clear/focused 移，
   远离 busy/cheap/cluttered）、关键任务首点不退化。

## 跨平台权重（清单不变，比重变）

- **小程序**：强偏单列清晰、明确任务块、克制表面分层、感知性能快；视觉层级比桌面少，
  主操作必须无歧义，加载态走上下文而非炫技（参考 WeUI 纪律化复用）。
- **Web 后台/大屏**：密度不是敌人，无纪律的密度才是。重点在间距阶梯、栅格、列表/详情/表格
  模板、克制用色；目标"密而透气"，有可见阅读路径、一个主导操作区、强封装的次要元数据
  （参考 Ant 8 栅格 + 邻近律）。
- **移动端**：靠狠抓重点——一个主导任务、每屏 2–3 个有效文字层级、原生感图标、动效澄清
  转场而非装饰；小视口里元素相互竞争是最快丢专业感的方式。

## 交付物（每次产出）

1. 带标注的诊断（每条问题 + 所属 gap + 证据，截图/数值）
2. before → after 改动清单（绑组件/token/数值）
3. 实际实现 diff（在受约束杠杆内）
4. 对照验收标准的自检（见 full-essay「Acceptance criteria」：无功能回归、5 秒测试过、
   token 合规、状态覆盖完整、动效有用非装饰、响应/主题 QA 过）

## 给 AI 的可复用指令模板

> "仅做视觉质感精修。保留现有结构、流程、业务逻辑、内容语义。不增删功能/步骤/字段/操作。
> 用 craft 清单诊断，按七类 gap 归因，只对间距/层级/排版/色彩角色/表面/图标/状态/感知性能/
> 动效提改动。所有改动以 before → after delta 给出，附理由、token 引用、验收点。"
